# State-action datasets

The four datasets DPDGen is evaluated on, one per process. Each is the set of
decision points a normative decision policy `pi_norm` reaches while driving its
process, together with the action it takes there:

```
((M, tau), a)   with   a = pi_norm(Omega((M, tau)))
```

This is the data described in Section 6.2 of the paper. It is the *only* data
the search sees: DPDGen simulates the normative policy once, records these
decision points, and then scores every candidate policy in the population by
replaying them. Conformance (Eq. 4) is measured over exactly these rows, so
the decision counts here are the `dec(pi)` the paper reports.

| File prefix  | Category | Process                                  | Normative policy | Decision points |
|--------------|----------|------------------------------------------|------------------|-----------------|
| `batching`   | Cat I    | Transportation, simultaneous execution   | `pi_batch`       | 491             |
| `choice_sl`  | Cat II-a | Assembly, time-based SLA                 | `pi_sla`         | 484             |
| `ratelimit`  | Cat II-b | Dual manufacturing, number of executions | `pi_rate`        | 486             |
| `priority`   | Cat II-c | Manufacturing, priority on data          | `pi_prio`        | 489             |

Regenerate with `python export_datasets.py` from the repository root. The
files are deterministic: the simulations are fully seeded, so a regeneration
reproduces them exactly rather than approximately.

## `<prefix>_state_action.jsonl`

One JSON object per decision point, holding the state `(M, tau)` — for every
place, every token with its availability time and its attribute values:

```json
{"decision": 0, "rollout": 0, "clock": 3.45,
 "places": {"waiting_1": [{"time": 5.29, "value": {"priority": 8}}],
            "waiting_2": [{"time": 3.45, "value": {"priority": 3}}],
            "machine":   [{"time": 0, "value": {"machine_id": 1}}]},
 "action": "postpone"}
```

| Field      | Meaning                                                     |
|------------|-------------------------------------------------------------|
| `decision` | index of the decision point, 0-based over the whole dataset  |
| `rollout`  | which simulation replication it came from                    |
| `clock`    | simulation time `tau` of the state                           |
| `places`   | the marking `M`: place -> tokens, each with `time` and `value` |
| `action`   | the transition `pi_norm` fires, or `postpone`                |

The state is stored rather than the observation `Omega((M, tau))` because every
candidate policy instantiates its own observation function through the feature
terminals it uses — so the features are derived on the fly, not fixed in the
data. The `time` of a token is when it becomes available, which is what the
`ALL` / `ENABLED` distinction turns on: a token is in `M^ENABLED(p)` when
`time <= clock`, and in `M^ALL(p)` regardless.

The format is lossless — a state can be rebuilt and any policy re-evaluated on
it, without running the simulator:

```python
from export_datasets import load_state_action
from ga_batching_conf import REFERENCE_POLICY

states, actions = load_state_action("data/batching_state_action.jsonl")

divergences = sum(REFERENCE_POLICY.evaluate(s) != a
                  for s, a in zip(states, actions))
print(f"conformance = {1 - divergences / len(states)}")   # 1.0
```

## `datasets.json`

Per process: the normative policy as a listing, the rollout count and horizon
it was recorded under, the trace seed base, the action transitions `T_A`, and
the action distribution.

## Provenance

Generated by simulating each process's Petri net under its normative policy for
`n_rollouts` independent replications of `horizon = 60` time units, with the
rollout count per process chosen so that the recorded trace holds roughly 500
decision points (Section 6.2). Every replication is seeded from the driver's
own `trace_seed_base`, recorded in `datasets.json`.

`tests/test_datasets.py` checks that these files reproduce the recorded actions
under the normative policies.
